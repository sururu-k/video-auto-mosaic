## 判定基準（重要）

**`RULES.md` が推していた「元映像との平均絶対差」は、この素材では使えなかった。**

| 指標 | 未塗装 | 塗装 | 最良の単一閾値での総誤り |
|---|---|---|---|
| フレーム全体の平均絶対差 | p50 4.2 / max 5.1 | p50 4.4 / min 1.3 | **41.9%** |
| 16x16ブロックの最大平均絶対差 | p50 10.9 / max 23.2 | p50 25.3 / min 8.1 | 14.8% |

crf 16 の再エンコードでも粒状ノイズの差分が大きく、**塗装フレームのほうが
フレーム平均差分が低いことすらある。**

採用した基準は**モザイクの構造そのもの**を見る:

- `render.pixelize_plane` は 20px 格子にスナップして各セルを平均色1色に潰す
  ＝ **モザイク領域はセル内分散がゼロになる**
- 画面を 20x20 の 96x54 セルに分割し、「元のセル内 std >= 6 かつ
  出力のセル内 std < 元の 0.35 倍」のセルを数える
- **潰れたセルが 2個以上ならモザイクあり**

分離（無作為60窓 × 100フレーム = 5900 で校正）:

```
未塗装 n=2802: 0が2800, 1が2, 2以上が0
塗装   n=3098: 0が2, 1が0, 2-15が29, 16以上が3067  中央値73
```

未塗装側の最大値 1、塗装側の第1パーセンタイル 16。**閾値2に対して8倍の余裕。**

外れる向き:

```
report塗装なのに画素で見えない    56 / 21030 (0.266%)  ← 測定の盲点
report未塗装なのに画素でモザイク   0 / 21030 (0.000%)  ← 危険側
```

**素通しを見逃す側には一度も外れない。** 盲点の正体は「元がもともと平坦な場所に塗った」
ケース（`source std < 6` でセルが対象外になる）。

位置合わせも検証済み（±1フレームずらすと差分が増える。`uncovered_ranges` の境界が
フレーム単位で一致）。

## 測れなかったこと

### 原理的に測れない

- **モザイクが対象の上に乗っているか。** GT が座標を持たない。今回言えるのは
  「そのフレームに**どこかに**モザイクがある」まで。
  **「検出はしたが矩形が対象の70%しか覆っていない」型の漏れは1件も測っていない。**
  `docs/09` が「見つかった漏れ52件のうち半分以上がこの型」と書いている以上、
  **被覆 75.3% は実際の漏れの上限ではなく、下限を過小に見積もったもの**
- **2人以上映る場面でどちらが塗られたか。** 上下/左右の半分で見る代替を試したが、
  2人の局部が同じ半分に収まる場合と区別できないので**証拠にならない**
- **誤検出率・precision。** 78区間は他社の弱点で層化された標本

### やらなかった

- `--infer-size 1280` での再検出（7:41 の差の切り分け。GPU を使うため）
- デスパイク off のコードでの焼き直し（上の32フレームが消えるかの確認）
- `segmenter.py` を陰嚢・挿入区間に当てる
- 完全沈黙3区間の目視確認（画素は「塗られていない」としか言わない。
  そこに対象が映っていることは他社の漏れ指摘という第三者の証言に依存している）

## どう読むべきか

`docs/03` の「78区間のうち77件で反応した（99%）」は区間単位の指標としては正しいが、
**完成品の品質をまったく表していない。** 同じ区間を1フレーム刻みで画素から見ると
24.7%・172.8秒が塗られていない。実害の中心は完全沈黙3件ではなく、
**24:20 の 21.5秒連続のような区間内の長い穴**にある。100%被覆は 78件中 30件。

塗られた 15846 フレームのうち **52.7% はそのフレームに検出が無い。**
「75.3% 塗った」を成果として読んではいけない。

一方で**この道具は自分が塗っていない場所をほぼ正確に申告している**（逆向きの誤りは 0/21030）。
`RULES.md` 0 の「黙って素通しを作らない」は守られている。例外は
`det.json` に検出があるのに素通しの 32 フレーム（デスパイクが捨てた帯）と、
**申告が動画の 68% を指していて人手チェックの導線として機能していないこと。**

他社が漏らした場所でうちも漏らしているのは、
**検出できていない陰嚢（被覆52%）と、検出できても穴が長く続く場面**。
前者はクラス定義の問題で設定では埋まらない。後者は `--estimate-gaps` と memory の設定で
動く範囲にあるが、**それは推測で塗る割合をさらに上げるということ**で、
既に半分が推測であることを踏まえると、被覆率の数字を上げても中身は薄くなる。
