# 再監査 2026-08-23

コア（`detector` / `temporal` / `render` / `video` / `corrections` / `cli`）と
Web層（`review.py` / `webapp/` / `frontend/`）を別々に監査した結果。

**確実に再現できたものだけを載せる。** 各項目に「どちらの方向に外れるか」を書いた。
この道具では漏れる側が致命的で、塗り過ぎ側は許容できる。

## 直したもの

| # | 内容 | 方向 | 状態 |
|---|---|---|---|
| W-1 | `set_corrections()` が `history` を残すため、`undo` が無関係な修正を末尾から削る | **漏れる** | 修正済 |
| W-2 | 手描きの「補間して展開」が既定で corrections を全消しする | **漏れる** | 修正済（既定を merge に） |

### W-1 の詳細（いちばん重い）

`set_corrections()` は `self.corrections` を丸ごと差し替えるが `self.history` に触らない。
`undo()` は「末尾から `added` 件を落とす」実装なので、差し替え後は別物を削る。

踏む手順は3手。

1. 検査キューで「漏れている」を span=5 で確定（`added=11`）
2. 別端末のタイムライン画面が、起動時に読んだ古い一覧を `POST /api/corrections`
3. 「ひとつ戻す」→ 手順1の11件ではなく、既存の末尾11件が消える

消えるのは `add`（漏れを塞いだ矩形）なので、**そのフレームは素通しに戻る。**
1周ぶんの目視検査が無駄になる。

### W-2 の詳細

`handdraw.expand()` の `merge` が既定 False。画面のチェックボックスも既定オフ。
つまり既定操作で、検査キューで積んだ修正が全部消える。

さらに corrections.json だけを書き換えて `.progress.json` の history を残すので、
次の undo が W-1 と同じ経路に入る。判定は「塞いだ」と表示されたまま、
塞いだ矩形が存在しない状態になる。

## 未修正（重い順）

### C-1 【致命的・漏れる】パス1のデコードサイズが ffmpeg と一致しない解像度がある

`automosaic/video.py` の `detection_frame_size()`。

```python
return w - (w % 2), h - (h % 2)   # 「ffmpeg は偶数に丸める」というコメントは誤り
```

`scale` フィルタの `force_divisible_by` は既定1なので奇数も出す。加えて ffmpeg は
四捨五入、こちらは切り捨て。二重にずれる。

`run_detection` は `dec_w * dec_h * 3` バイト単位でパイプを読むので、1バイトずれると
**以降の全フレームが前フレームと混ざった斜めの画像になる。例外は出ない。**

実測で壊れる解像度:

| `--infer-size` | 不一致になる入力 |
|---|---|
| 640 | 854x480、720x480、1280x534 |
| 960 | 854x480、848x480、1920x1002、1918x1080、1280x692 |
| 1280 | 854x480、848x480、720x480、1918x1080 |

**854x480（480pワイド）と 720x480（DVD/NTSC）が壊れる。**
手元の 640x480 と 1920x1080 はたまたま一致していたので顕在化していない。

直し方: `dec_w`/`dec_h` を計算で当てるのをやめ、`ffprobe` で実際の出力サイズを取るか、
`scale` に `force_divisible_by=2` を明示して計算式を ffmpeg に合わせる。

### C-2 【致命的・漏れる】パス2がパス1より長いと素通しになる

`automosaic/cli.py` の描画ループ。

```python
else:
    # パス1より長い場合。素通しはしない（判断できない = 潰す）
    boxes = last_boxes
```

`last_boxes` はパス1最終フレームの領域。**そこが空なら以降は全部モザイクなしで通る。**
コメントの主張が成り立たない。警告もレポートも出ない。

踏む経路が3つある。

1. README の「まず短く試すなら `--limit-frames 300`」で検出 → `--reuse-detections` で本編を描画
2. 途中保存（`--checkpoint-every`）を `--reuse-detections` で読む
3. パス1のデコードが途中で止まった場合（C-3）

直し方: `n_frames` が実尺より短いときは**エラーで止める**。素通しを黙って作らない。

### C-3 【重大】パス1のデコード失敗が `idx > 0` なら黙殺される

`if proc.returncode not in (0, None) and idx == 0:` なので、1フレームでも読めていれば
例外にならない。壊れたファイルで実測すると 90 フレームのはずが 45 で正常終了した。
C-2 と合わさると、後半が素通しの出力が正常終了として出てくる。

### C-4 【重大・漏れる】`--reuse-detections` が `complete` も解像度も検証しない

- `save_detections` が書く `complete: False` を読むコードがリポジトリに存在しない。
  途中保存を読むと部分的な `n_frames` が採用され、C-2 の経路に入る
- JSON の `width` / `height` を読まないので、**解像度違いの検出JSONを流用しても警告が出ない**。
  実測では領域が左上に寄り、幾何フィルタでも検知されなかった

`data/myvideo5/compare/` に 640x480 と 1080p の検出JSONが併存しているので、取り違えは現実的。

### C-5 【重大・漏れる】`corrections.apply()` が範囲外フレームの手修正を黙って捨てる

`if frame not in out: continue`。`n_frames` を超えるフレームの手修正は、例外も警告も
件数報告もなく消える。CLI は読み込み件数しか出さないので、何件適用されたか分からない。

**手修正は最後の砦なので、静かに落ちるのは特に悪い。**

### C-6 【重大・漏れる】`--estimate-gaps` 無しが明示指定を黙って上書きする

`--memory 20` を渡しても 2 に落とされる。`--motion-weight 3.0` も 1.0 に。
表示もされない。

**README の表と実挙動が食い違っている。** `--motion-weight | 2.0` と書いてあるが、
既定実行では 1.0。

### C-7 【重大・漏れる】`max_area_ratio 0.35` がアップの検出を丸ごと落とす

面積比 0.35 超の検出はトラック化の前に捨てられるので、そのフレームは検出0件と同じになる。
実測で 0.34 なら 60/60 被覆、0.36 で 0/60。

**「大きく映っている＝いちばん塞ぐべき」場面で被覆が0になる方向の閾値。**
接写・全画面のアップで踏む。

### W-6 【重大・漏れる】タイムラインの取り消しが remove+add の組を割る

検査キューの「でかすぎる」は remove と add を必ず組で積むが、タイムライン画面の
`undoLast` / `deleteUnderCursor` は1件しか消さない。組の末尾は add なので、
add だけ消えて remove が残り、そのフレームは**自動領域も手修正も無い完全な素通し**になる。

### W-7 【重大】サーバ再起動をまたぐと同じジョブを二重起動できる

二重起動を弾いているのはプロセス内のレジストリだけ。再起動するとレジストリが空になり、
`meta.json` の pid を見ないので、同じ `output.mp4` に2本が書く。

### W-8 【軽微】`/api/mark` の frame クランプで別のフレームに判定が付く

`frame=999999` を送ると応答は 999999 を返すが、`.progress.json` には最終フレームに
記録される。範囲外を弾かずに黙って端へ寄せている。

### W-9 【軽微】ジョブIDの一意性保証が空振り

`new_job_id` は「そのIDのディレクトリが存在するか」しか見ず、発番時に予約しない。
実際の一意性は `token_hex(2)` の16ビットだけに乗っている。同一秒内で50個引くと
衝突確率 1.85%。`tests/test_webapp.py` の間欠失敗はこれが原因で、テストの問題ではない。

### その他

- `estimated_only_ranges` の `min_len=5` が既定。`--estimate-gaps` 無しだと推定のみ区間は
  2〜4フレームになりがちで、まるごと報告から消える。実測の「漏れは0.2秒の粒度で出入りする」
  と噛み合っていない
- 字幕付き mkv → mp4 出力で ffmpeg が死ぬが、`BrokenPipeError` が先に飛んで
  stderr の本当の理由が表示されない
- 奇数解像度は `render.py` で落ちる。`--detect-only` は通るので、検出に数時間かけた後に
  描画で落ちる。パス1の前に検査すべき
- `temporal.py` の冒頭 docstring の処理順が実装と食い違っている（結合とデスパイクの順序）
- HTML の静的マークアップが Preact 移行でデッドコードになった。JS が読めない状態では
  **押しても何も起きないボタンが並んだ画面**が出る

## 見たが問題なかったところ

- **モザイクの被覆**（`render.py`）: ブロックサイズ2〜16 × 位置/サイズ乱数 × 8bit/10bit で
  3000ケース×2 のプロパティテスト。**要求矩形の内部が塗られなかったケースは0件**
- 10bit 経路、VFR、音声なし素材、境界条件（検出0件、`n_frames=1`）はいずれも正常
- トークン検証は全経路（静的・画像・動画・API・SSE・アップロード）で効いている
- XSS（`innerHTML` / `eval` が一切無い）、CSRF（`SameSite=Lax`）
- 座標変換のブランド型は、判定を送る経路で一貫している
- アップロードはメモリに載せずディスクへ流している
- 全置換（`str.replace`）による意図しない変更は、コア6ファイルに残っていない
