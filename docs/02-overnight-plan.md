# 夜間の自律作業計画

作成 2026-08-23。利用者が就寝中に自律で進める作業の手順書。
各項目は「終わったか判定できる条件」を持たせてある。判断に迷う変更、後戻りが
効かない変更、素材を消す操作は行わない。

## 守ること

- **テストが通らない変更はコミットしない。** `tests/test_render.py` と
  `tests/test_review.py` の両方が通ることを毎回確認する
- **既定値を勝手に大きく変えない。** 変えるなら実測の根拠とセットで、README に理由を書く
- **素材・過去の出力を消さない。** 整理は `data/**/_old/` への移動で行う
- **push は毎回行う。** 朝に見られる状態にしておく
- 目視判定は当てにならないことが実証済み（見落としと誤検出の両方が出た）。
  **独立した2つ以上の判定が一致したものだけを確定**として扱い、食い違いは
  「要確認」として残す。1つの判断で他を覆さない

## 作業項目

### A. 30分素材のベンチマーク（最優先・時間がかかる）

素材 `C:\Users\shieru_k\Downloads\video\マイビデオ-3.mp4`（1920x1080 / 30fps / 55,303フレーム）。
他社ツールで処理した結果に対する**人間検証済みの漏れ一覧**が
`data/bench3/leaks_reported.md` にある（84区間、時刻と部位つき）。

1. 検出を回す（実行中: `data/bench3/det.json`）
2. 84区間を機械可読な形に変換する（`start_sec`, `end_sec`, `part`）
3. **各区間でうちの検出器が反応しているか**を集計する。ここが本題。
   他社ツールが漏らした箇所は「局部が確実に映っている」ことが保証されているので、
   うちがそこで沈黙していれば、それがうちの穴になる
4. 結果を `docs/03-benchmark-myvideo3.md` に書く。数字だけでなく、
   沈黙している区間の特徴（構図・動き・明るさ）を並べる

**終了条件**: 84区間それぞれについて「検出あり/なし」と最大スコアが表に出ていること。

### B. マイビデオ-5 の未検査区間を潰す

**終了条件**: 全区間を最低1回検査し、漏れが見つかった区間は2回目の検査も済んでいること。

### C. 出力側の独立検証ゲート（未実装の設計項目）

## F. Webアプリ化（追加。2026-08-23 深夜に利用者から指示）

現状の `automosaic/review.py` は標準ライブラリの `http.server` で書いてある。
依存ゼロで即起動できる利点はあったが、**アップロードから完成品の受け取りまでを
一貫して扱う**なら自前で書く意味がない。

### 目指す流れ

```
アップロード -> 自動でモザイク -> 画面でチェック -> 手で直す -> 完成品をDL
                    |                                   |
              進捗をリアルタイム表示            修正が学習データに積まる
```

### 技術選定

- **FastAPI + uvicorn**。理由は (1) ファイルアップロードが標準、(2) 3〜4時間かかる
  処理の進捗を WebSocket/SSE で流せる、(3) ルーティングとバリデーションが揃っている
- 画面側は**ビルド不要の素のJS**を維持する。外部CDN禁止、オフラインで動くこと
- `python-multipart` が必要（FastAPI のアップロードに要る）

### 作業支援ツールとしても開く

いまの仕組みは既に「任意の位置に矩形を置いて時間方向に補間し、YUV平面で焼く」もの。
自動検出を使わずに**手で全部描く**使い方に開く。競合の PixelTrack が自動検出を捨てて
トラッキング＋手動編集に振ったのと同じ方向だが、うちは両方持てる。

- 検出をかけずに空の状態から始められる
- 好きなフレームで矩形を置き、次のキーフレームまで補間（`annotations_to_corrections.py`
  の仕組みがそのまま使える）
- 検出結果は「下書き」として扱い、採用/却下できるようにする

### 保存の構造

修正済みの動画とフィードバックを1件ずつ残す。**修正箇所は全部「この場面のこの位置に
局部がある」という正解データ**なので、案件をこなすほどデータが溜まる。

```
data/library/<ジョブID>/
  source.mp4          元素材
  output.mp4          完成品
  det.json            検出結果
  corrections.json    手修正
  leakcheck/          漏れ検査の記録
  dataset/            画像 + YOLOラベル
  meta.json           日時・設定・統計・漏れ件数・処理時間
```

`meta.json` には後で集計できるだけの情報を入れる。どの設定で何件漏れたか、
手修正が何件必要だったかが案件ごとに残れば、改善の効果を測れる。

### 作る順番

1. ジョブの受け皿とライブラリ構造（アップロード -> 保存 -> 一覧）
2. 処理の起動と進捗配信（既存の CLI をサブプロセスで呼び、進捗を拾って流す）
3. 既存の検査キュー画面を FastAPI 側へ移植
4. 手描きモード（検出なしで始められる）
5. 完成品のダウンロードとデータセット書き出し

### 制約

- **既存の `automosaic/review.py` は壊さない。** 利用者が今夜使う可能性がある。
  新しいものは `automosaic/webapp/` に別途作り、動くようになってから移行を判断する
- `automosaic/cli.py` `detector.py` `temporal.py` `render.py` `video.py` は変更しない。
  Webアプリはこれらを呼ぶ側に徹する
- アップロードされる素材は成人向け。**LANに出す以上トークン必須**は維持する

**終了条件**: アップロードした動画が自動処理され、画面でチェックでき、
完成品をダウンロードでき、`data/library/` に一式が残っていること。
