# ベンチマーク: 他社ツールが漏らした区間でうちは検出できるか

測定日 2026-08-23（夜間の自律作業）

素材 `マイビデオ-3.mp4` / 1920x1080 / 30fps / 55,303フレーム / 30.7分

## 前提

同業者が使っている他社ツール（動画自動モザイクくんと推定）でこの素材を処理した結果に対し、
**人間が全編を検証して作った漏れ一覧**を利用者から提供された。

各区間は「他社ツールがモザイクを外した＝そこに局部が確実に映っていた」ことを
人間が確認したもの。つまり**正解が保証された区間**であり、検出器の性能を測る
ベンチマークとして使える。

**他社ツールの成績: 78区間 / 合計 701秒。30.7分の動画のうち 38%の時間で漏れていた。**

## 結果

| | |
|---|---|
| 他社が漏らした区間 | 78件 / 合計 701秒 |
| **うちの検出器が反応した区間** | **77件 (99%)** |
| 沈黙した区間 | **1件** (7:41 陰嚢、1秒) |

**他社ツールが漏らした箇所のほぼ全てで、うちの検出器は反応している。**

## 測り方で結果が変わった

最初、5フレームおきの間引き検出で測ったところ 64/78（82%）だった。
沈黙した14区間を**全フレームで検査し直したら13区間で検出できた**。

| 検査 | 検出できた区間 |
|---|---|
| 5フレーム間引き | 64/78 (82%) |
| 沈黙区間を全フレーム再検査 | **77/78 (99%)** |

間引きの影響は区間の長さに強く依存する。

| 区間の長さ | 5フレーム間引きでの検出率 |
|---|---|
| 11秒以上 | 24件中24件 (100%) |
| 4〜10秒 | 18件中18件 (100%) |
| 2〜3秒 | 23件中18件 (78%) |
| **1秒** | **13件中4件 (31%)** |

1秒＝30フレームなので、5フレーム間引きでは6点しかサンプルしない。
そこに検出が出るのが数フレームだけなら、簡単に取りこぼす。

**短い事象を測るときに間引いてはいけない。** 検出器の性能を過小評価する。
実際、間引きの結果だけを見ていたら「1秒の事象に弱い」という誤った結論を出していた。

## この数字の意味と限界

**意味すること**: 他社ツールが取りこぼした場面のほぼ全てで、うちの検出器は
対象を見つけている。検出段階の性能で負けていない。

**意味しないこと**: 「うちなら漏れない」とは言えない。うちの漏れは2種類あり、

1. **検出できていない** — このベンチマークが測っているのはここ。78区間中1件
2. **検出できているが矩形が足りない** — マイビデオ-5 の実測では、
   見つかった漏れ52件のうち**半分以上がこの型**だった

このベンチマークは1だけを測っている。2は出力を見ないと分からない。
最終的な確認は目視検査になる。

**スコアが低いことは問題ではない**: 検出できた区間の最大scoreは 0.12〜0.57 と低い。
既定のしきい値（このモデルの標準は0.2前後）では半分近く落ちる。
`--conf 0.06` まで下げている判断が、この素材でも正しいことを裏付けている。

## 再現手順

```bash
# 検出（間引きあり。全体の傾向を見る用）
python -m automosaic 素材.mp4 --detect-only --infer-size 1280 --conf 0.06 \
  --frame-step 5 --detections det.json --checkpoint-every 2000

# 漏れ一覧を機械可読に
python tools/parse_leak_report.py leaks.md -o leaks.json

# 突き合わせ
python tools/benchmark_vs_report.py det.json --intervals leaks.json \
  --out benchmark.md

# 沈黙した区間だけ全フレームで再検査（間引きの影響を切り分ける）
python tools/recheck_intervals.py 素材.mp4 --intervals leaks.json \
  --only-silent silent.json --out recheck.json
```

## 検出できることと塞げることは別 — 実測

「区間内で検出器が1度でも反応するか」は 77/78 (99%) だった。
では「区間の全フレームにモザイクが乗るか」はどうか。同じ検出結果から、
時間方向の設定を変えて測った。

| 設定 | 78区間の全被覆 | 区間内フレーム被覆 | 動画全体の適用率 |
|---|---|---|---|
| **既定**（検出できた箇所のみ） | 26/78 | 66.6% | 61.6% |
| `--estimate-gaps` | 58/78 | 83.5% | 79.6% |
| `--estimate-gaps` + `--memory 20 --memory-before 20 --bridge-max 300` | **74/78** | **95.4%** | 93.9% |

**既定の「検出できた箇所だけ塗る」は、この素材では被覆が 66.6% にとどまる。**
推定で埋めると 95.4% まで上がるが、動画全体の 93.9% にモザイクが乗ることになる。

これは posture の選択そのもので、技術的にどちらが正しいという話ではない。

- 塗り過ぎを避けたい → 既定。ただし**区間の3割は塗られない**
- 漏らしたくない → `--estimate-gaps` と長めの memory。ただし**ほぼ全編にモザイクが乗る**

**注意**: この測定は5フレーム間引きの検出結果に基づく。4/5のフレームは検出が無く
補間頼みなので、既定の数字は実際より悪く出ている可能性がある。全フレーム検出で
測り直せば既定の被覆はもう少し上がるはず。ただし**傾向は変わらない**。

## この素材で分かったこと

1. **検出段階では他社に負けていない。** 他社が漏らした78区間のうち77区間で反応する
2. **被覆は設定次第で 66.6% から 95.4% まで動く。** ここが実際の勝負どころ
3. **完全に検出できない箇所が1つある**（7:41 陰嚢）。これは設定では埋まらない
